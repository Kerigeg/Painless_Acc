# 提瓦特会诊室

中文、本机优先的原神账号诊疗工具。流程：录入／UID公开展柜导入 → 可解释诊断 → 基础教学／教程 → 执行反馈 → 重新规划。当前重点为**月感电**，不是账号评分器、最优队伍搜索或完整战斗模拟器。

## 运行与预览

Node.js 22.12+（本次 Node 26.7 / macOS）。

```sh
npm ci
npm run dev -- --port 5173
```

访问 http://127.0.0.1:5173 。开发服务器同时提供页面与 `/api/showcase`，无需 API 密钥。

生产模式：

```sh
npm run build
npm start
# 可选：PORT=8080 HOST=0.0.0.0 npm start
```

生产服务器使用与开发环境相同的 UID API。**仅托管 dist 静态文件无法使用 UID 导入**；请运行 Node 服务。默认只监听本机。本次未部署公网、未推送 GitHub。

```sh
npm test             # 规则、数学、导入转换、服务端缓存测试
npm run test:e2e     # 先启动 dev，需本机 Google Chrome
```

浏览器测试使用隔离上下文与明确的测试夹具，不改动用户当前浏览器档案。真实接口另用 Enka 官方文档公开示例验证，结果见 [VALIDATION.md](./VALIDATION.md)。

## UID 导入

1. 游戏内打开角色展柜并启用“显示角色详情”。这不是获取全部角色的授权，也不需要密码、Cookie、验证码或米游社凭据。
2. 网站首页点击 **UID 导入配置**，输入 9／10 位 UID，读取公开展柜。
3. 检查角色、武器、圣遗物、面板和未知字段，勾选后点击合并。
4. 同名角色更新公开配置；保留角色 ID、当前队伍、保留角色、玩法目标、可用状态和历史。未展示角色不会删除。
5. 新角色的可用状态为“未知”，需玩家确认。导入后更新受影响诊断。导入前后快照记录于“反馈与历史”。

- 数据源为 [Enka.Network API](https://github.com/EnkaNetwork/API-docs/blob/master/api.md)，并非提瓦特小助手的私有接口。参考的是 UID → 公开展柜 → 配置分析的交互方式，没有抓取微信小程序或复制其数据。
- 只读取展柜中的详细配置；无法获得背包、未展示角色、完整仓库、地区解锁、材料库存或实际队伍。
- 识别名称哈希、SkillOrder、额外天赋等级、武器精炼的 0-based 数值、圣遗物 1-based 等级以及百分比单位；保留原始装备主副词条数值。
- 面板标记为“展柜快照（增益未知）”，不与装备再次叠加，也不假定战斗被动、命座与增益全都激活。
- 名称资料从 Enka 官方资料仓库获取。映射缺失时显示未知及物品 ID，不推测。个别缺失字段保留旧资料或未知，并在预览提示。
- 同账号重复导入不会新增同名角色或同部位重复装备。API 未提供可用于全仓库匹配的实例 ID：站内装备 ID 表示当前账号／角色／部位快照，**不是**游戏物品实例 ID，不声称能跨展柜快照识别一件被转移的装备。
- 不同 UID 不允许混进同一已绑定档案。使用独立浏览器档案或先导出旧档案；未提供跨账号同步。
- 私密／空展柜、格式错误、不存在、维护、限流、超时与未知映射都有真实状态；不显示伪造角色或成功结果。
- 服务端使用自定义 User-Agent、同 UID 并发合并、TTL 内缓存、429 冷却和有界缓存。缓存到期删除，不进行 UID 遍历。每次手动请求会将 UID 发给 Enka；静态名称资料请求发往其 GitHub 仓库。

## 月感电专项

新增砂糖、哥伦比娅、菲林斯、伊涅芙、爱诺、菲谢尔。输入“皇女”归一为菲谢尔，“伊涅夫”归一为伊涅芙。

- 区分开启月感电与提高月兆：本版已核实的开启者为菲林斯、伊涅芙、哥伦比娅；爱诺提高月兆但不能独自转化反应。未收录角色不视作确定没有相应能力。
- 专属规则检查水雷角色、月兆条件、雷云／水覆盖断点、菲林斯中途切人和爆发类型、爱诺／哥伦比娅能量等待、元素杯与职责、生存和魔导信息缺失。
- 三组有来源的练习模板只在全员已拥有、可用且不移除指定保留角色时才能应用。不会自动添加缺失角色或建议抽卡。
- 当前队伍生成有依赖的循环教程；先完成基线、确认低风险场景和时间预算。无需蒙德解锁假设、不花树脂、不刷随机装备。
- 六角色有职责、简化手法、天赋投入顺序和装备方向。养成阶段先验证瓶颈，不伪造尚未收录的材料成本。
- 圣遗物有限比较依当前角色与月感电职责进行；不会把菲谢尔的普通雷伤杯一概判错，不提供数值排名、套装最优分配或伤害提升百分比。
- “照做无效”降低相关结论确定性并改变下一次任务；“操作不出来”提供简化尝试；“够用”结束阶段。
- 雷云反应月感电与天赋直接月感电不混算。未实现全队伤害公式、月反应模拟、命座／魔导精确收益或所有新机制；普通计算工具明确不能代替月感电模拟。

## 保留的 P0／P1 能力

分步问诊、详细档案、本地 JSON 导入导出、未知值、独立规则、分层教学、术语、预算、依赖与停止条件、九种反馈分支、历史快照、手机／桌面布局。保留凯亚和芭芭拉旧教程与芭芭拉战技 1→2 的库存检查。

档案数值空白为 `null`；没有展示角色不代表未拥有。字符等级接受 1—100；武器仍是 1—90，未知天赋／装备不填0。导入／改动后重新核查依赖，旧记录保留且说明需要复核。

## 数据与持久化

浏览器键 `teyvat-clinic-v1`。不需要游戏登录，不依赖收费 AI。选择 UID 功能才联系第三方；档案保存在本机，清除浏览器数据会丢失，建议导出 JSON。

备份结构为 `schemaVersion: 1`、`profile`、`history`、`baseline`、`imports`。Zod 校验结构、ID 与装备合法性，导入限制约 5 MB，失败不覆盖。旧版 JSON 自动补充保守默认字段；因新增字段，旧任务可能需要重新核对，但历史不删除。导入快照最多100条，达到限制时拒绝新增而非静默删除。

当前没有服务端账号数据库、跨设备同步或自动读取背包。无效用户输入不覆盖最后有效本地数据。

### 新角色名称补充（2026-09-19）

当前 Enka 名称表未覆盖部分新角色。`src/data/character-identities.ts` 单独保存用户确认的显示名对应：`10000150 → 奥黛塔`、`10000148 → 阿罗夏`。此对应来自用户对实际导入角色的确认，上游游戏数据尚未独立核实；不包含技能、元素、天赋顺序或新反应数值。页面明确标注来源，不将名称识别等同于机制支持。

刷新时自动修复当前档案中对应的未知名称，历史快照保持原样；若已存在同名角色，不自动合并。其他缺失名称可在角色档案中校正，再次 UID 导入保留校正、装备归属和角色身份。
